The candidate link used `-Wl,--wrap=memcpy` and failed with the exact Zig diagnostic `error: unsupported linker arg: --wrap` (exit 1). `compiler-rt-test.log` retains the generated compiler-runtime symbol table. A later BFD-linker experiment has no retained output, so it is not evidence.

A subsequent review found that the saved candidate-callsite disassembly excerpt included bytes beyond the 10-byte function symbol. Its actual entry jump is valid, and its separate direct guard result remains tied to the run-04 DSO. Run 05 corrects the excerpt to the function extent.

An offline replay of the current parser against its retained text is recorded in `audit-result.json`. Its DSO and compiler-runtime whole-object hashes differ from run 04 because the DWARF line table embeds a different Zig cache directory; their relevant `.text` hashes are identical. The source snapshot used by run 05 has a recorded hash but was not retained as a file.
